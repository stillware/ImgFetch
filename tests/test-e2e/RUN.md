# ImgFetch e2e (real browser)

Playwright + Chromium suite. Every page and asset is generated by the test,
no internet needed.

## Prereqs

```bash
npm i playwright
npx playwright install chromium
```

(`npm i` inside `<playwright-install>` already did this on the dev machine.)

## Run

```bash
# DPR 1, headed under a virtual display (required for extension loading +
# tab capture). PLAYWRIGHT_PACKAGE points at the playwright install because
# ESM ignores NODE_PATH:
PLAYWRIGHT_PACKAGE=<playwright-install>/node_modules/playwright xvfb-run -a node tests/test-e2e/e2e.mjs --dpr=1

# DPR 2 (the N1 case, 20,000px page on a high-DPI screen):
PLAYWRIGHT_PACKAGE=<playwright-install>/node_modules/playwright xvfb-run -a node tests/test-e2e/e2e.mjs --dpr=2

# Microsoft Edge (needs microsoft-edge-stable installed):
PLAYWRIGHT_PACKAGE=<playwright-install>/node_modules/playwright xvfb-run -a node tests/test-e2e/e2e.mjs --dpr=1 --browser=edge
```

Results: `tests/test-e2e/results-<browser>-dpr<N>.json` (raw evidence
per phase). The run FAILS (exit 1) on any phase failure and on any
`console.error` / `pageerror` / unhandled rejection in the service worker,
popup, offscreen document or content scripts.

## Phases

- **P0** extension loads, service worker alive
- **P1** SCAN_PAGE on the fixture gallery (40 imgs, lazy, srcset, picture,
  CSS bg, iframe, inline SVG)
- **P2** DOWNLOAD_MANY, 12 files on disk, PNG magic bytes verified
- **P3** stitch of a 20,000px page at DPR 2 through the REAL offscreen
  document, the N1 case: STITCH_BEGIN with the planner's output, real tiles,
  output decodes at the planned dimensions, not blank.
  NOTE: `chrome.tabs.captureVisibleTab` needs the activeTab user gesture,
  which Playwright cannot synthesize, so the tile-*capture* half of
  `captureFullPage` is NOT TESTED (see NOT_TESTED.md); the planner+stitcher
  contract (the actual N1 bug) IS tested here with real pixels.
- **P4** stitch of a 3,000px page at DPR 1, baseline
- **P5** service-worker kill ×3 (CDP `ServiceWorker.stopAllWorkers`) during
  a 100-image bulk, restart, no duplicate files, queue recovers (N4)
- **P6** DOWNLOAD_ZIP of 50 images, valid zip on disk
- **P7** 100 MP canvas allocation probe inside the offscreen document,
  decides the N1 area cap (lower to 60 MP if it crashes/stalls)
- **P8** zero console.error / pageerror across all contexts

## Fixture server

`fixture-server.mjs`, plain Node `http`, serves generated PNGs (pure-Node
PNG writer), the gallery / big-gallery / tall pages, and hostile endpoints
(wrong content-type, 403-without-referer, 404, 429, slow, 30 MB).

Standalone: `node tests/test-e2e/fixture-server.mjs` → http://127.0.0.1:8765

## capture-e2e.mjs (FIX 3 + FIX 4, phases C1-C11)

Real-browser suite for the fixes work: capture on every tab the browser
allows, and full-fidelity screenshots. Runs under the same xvfb setup as
above:

```bash
PLAYWRIGHT_PACKAGE=<playwright-install>/node_modules/playwright xvfb-run -a node tests/test-e2e/capture-e2e.mjs --dpr=1
```

DPR 1 runs all phases; other DPR values run the DPR-sensitive phases
(seams, crops, parts) only.

Honest automation limit: `chrome.tabs.captureVisibleTab` needs the
<all_urls> or activeTab permission, which Playwright cannot synthesize (no
user gesture), so the final tile-*capture* call is replaced by a CDP
`Page.captureScreenshot`. Everything else is the REAL path: the real planner
(`core/fullpage-capture.js`), the real in-page logic (`content/scanner.js`:
describeScrollContext, scrollCaptureTarget, waitForViewportStable,
setFixedHidden, ensureTargetVisible) driven exactly like the worker drives
it, and the REAL offscreen stitcher (STITCH_BEGIN/TILE/END) in the
extension's own offscreen document.

Device pixel ratio: this Chromium build ignores
`--force-device-scale-factor`, so each test page sets its DPR through CDP
`Emulation.setDeviceMetricsOverride` (verified: `window.devicePixelRatio`
and bitmap sizes follow it), and screenshots go through CDP
`Page.captureScreenshot`, because Playwright's `page.screenshot()` ignores
the emulated scale factor. The reference rendering for the seam comparison
is a CDP full-page capture (`captureBeyondViewport` with a full-height clip)
at the same DPR.

- **C1** FIX 3: CAPTURE_VISIBLE on chrome://newtab (empty URL) is refused by
  the browser: localized error, nothing captured, nothing captured from
  another tab.
- **C2** FIX 3: extension page, injection forbidden: honest localized refusal.
- **C3** FIX 4: seam-free stitching at DPR 1, 1.25, 1.5, 2 and 3: every
  100px row of a synthetic page carries a unique color, so the row-
  sequence check detects any seam, duplicate or shift pixel-accurately;
  a CDP full-page reference rendering is compared as well, after a
  self-check (Chromium's CDP renderer corrupts very tall captures at
  DPR 3, so only its self-consistent region is compared there).
- **C4** FIX 4: inner scroll container captured whole, rows in order.
- **C5** FIX 4: sticky header + fixed banner appear exactly once.
- **C6** FIX 4: lazy images decoded in the stitched output.
- **C7** FIX 4: page state fully restored after capture (scroll position and
  changed styles, even on failure).
- **C8** FIX 4: very long page split into parts, every part at full
  resolution, whole page covered.
- **C9** FIX 4: area crop exact at DPR 1, 1.25, 1.5, 2 and 3; PNG `quality`
  argument has no effect (still lossless).
- **C10** FIX 4: peak heap measured during a 64 MP stitch (offscreen +
  worker), at dpr=1 only.
- **C11** FIX 4: annotate editor with an 8000x8000 image: drawing speed,
  Undo/Redo, Save, Copy, Discard, zero page errors.

Results: `tests/test-e2e/results-capture-<browser>-dpr<N>.json`. The run
FAILS (exit 1) on any phase failure and on any `console.error` / `pageerror`
/ unhandled rejection in any context.
